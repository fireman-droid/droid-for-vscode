# 审阅文件改动

Review 把文件改动和上下文放在同一个页面：未修改的内容继续可见，
新增与删除位置使用 `+` / `−` 和颜色标记。

## 打开 Review

从聊天中的文件修改记录点击 **Review**，查看该次编辑；
也可以运行 **Droid: Review Changes**，集中浏览变更文件。

先检查顶部当前查看的范围，例如 **Recorded edits** 表示会话记录的编辑操作。
记录的某次编辑和文件当前的工作区状态可能不同。

## 阅读与切换视图

- 在文件列表中选择目标文件，或使用筛选框缩小范围。
- 使用统一视图，在同一列查看增删；使用左右分栏，对照修改前后两份内容。
- 通过上一处／下一处修改跳转，避免在大文件中反复寻找改动。
- 完成检查后使用 **Mark viewed** 标记已读。

已读标记只记录审阅进度，不等于代码正确，也不会自动提交改动。
提交前仍需检查范围和实际结果。

## 完整文件与历史版本

完整文件比较需要该次修改前后的版本内容。
当版本记录完整时，Review 会显示整个文件，在改动处标出差异。

如果旧会话只保存了局部补丁，且对应完整版本无法恢复，页面会提示：

> Full file comparison unavailable. Only the saved change excerpt is shown below.

它表示当前只能看到已记录片段。工作区里的最新文件不能直接当成历史编辑时的完整版本，
因为此后可能又有其他修改。再次刷新不会凭空补回缺失的历史内容。

如果刚发生的新修改也只显示片段，请附上文件类型、修改时间、对应会话及脱敏截图，
按 [排障指南](TROUBLESHOOTING.md) 提供相关日志，便于定位版本采集链路。

## 回退前先确认范围

撤销能力取决于该条记录能否确认完整的修改内容。
若界面提示记录不一致或自动撤销不可用，先检查文件和 Git 状态，
不要把不完整的片段当作整份文件覆盖回去。

Review 是审阅入口。具体支持范围与当前限制见 [能力说明](CAPABILITIES.md)。
