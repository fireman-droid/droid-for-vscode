# 模型与服务渠道

聊天模型从本机 Droid 读取；编辑器代码补全使用[独立的配置入口](AUTOCOMPLETE.md)。
运行 **Droid: Manage Models**，可以管理自定义模型的接口、显示名称和启用状态。

## 官方、BYOK 与混合

模型菜单和模型管理页提供三种显示范围：

| 范围 | 展示内容 |
| --- | --- |
| 官方 | Droid 提供的内置模型 |
| BYOK | 使用你自己的接口和 API Key 配置的模型 |
| 混合 | 两类模型一起显示 |

这个偏好同步到聊天、BTW、Spec 和 Mission 的模型选择。
切换显示范围不会自动更换当前模型，也不会删除模型配置。

## 添加一个渠道

1. 在模型管理页选择 **添加模型**，或通过服务商旁的添加入口创建接口。
2. 填写接口别名和服务方给出的 **Base URL**。别名用于区分线路，例如“主用接口”或“备用接口”。
3. 选择该服务实际支持的协议。
4. 如需密钥，保存后在编辑器弹出的安全输入框填写 API Key。
5. 获取服务提供的模型列表并选中要导入的模型，或手动填写模型 ID。

Base URL 包含服务方要求的基础路径；不要把 API Key 写到地址里，也不要把最终请求路由当作基础地址。
同一接口下的模型共用连接配置。

| 接口类型 | 适用情况 |
| --- | --- |
| OpenAI Chat Completions | 仅提供 Chat Completions 的兼容服务 |
| OpenAI Responses | 提供 Responses API 的服务 |
| Anthropic Messages | 提供 Anthropic Messages API 的服务 |

“兼容 OpenAI”不一定表示支持 Responses；以服务方文档为准。

## 模型 ID、别名和同名模型

**模型 ID** 是请求上游服务时使用的名称。**模型别名** 只改变界面中的显示名称。
通过模型的更多操作修改别名，不需要为了改名字重建接口。

可以在不同渠道添加相同的模型 ID，各渠道的地址和配置独立保留。
如果显示名称重复，使用能区分渠道的别名，例如“主线 · Model A”和“备用 · Model A”。
同一批导入中的重复别名也需要先区分。

## 禁用与恢复

在模型的更多操作里选择 **禁用模型**，配置会保留，该模型不能再被选用。
需要重新使用时选择 **恢复模型**。

禁用不会删除地址和密钥，也不会强行中断已经开始的回复。
已禁用的模型可以继续编辑配置，但恢复后才能重新选择或验证。

## 验证与切换

**保存**用于写入配置；**验证模型…** 或 **保存并验证…** 会在确认后请求一次真实模型回复，
可能产生服务费用。获取到模型列表不等于模型已经能正常回复。

验证失败时，检查接口协议、Base URL、模型 ID、密钥权限和服务额度，
保留面板给出的原始错误便于定位。不要因为验证失败反复新建相同模型。

配置可用后，从输入框旁的模型菜单选择它。
更多运行条件及限制见 [能力说明](CAPABILITIES.md)，连接与日志问题见 [排障指南](TROUBLESHOOTING.md)。
