## 优先验收：连接与可见进度

现有生产路径与本轮新补同步逻辑需要确认真实使用表现，不重新实施同一套架构。

- 开机后有旧 daemon 登记/PID 复用、长历史、普通恢复和连续切换：记录从打开到
  可发送的完整时间，区分目录、历史、IDE 握手和页面渲染，不以局部微基准推算总时长。
- 长时间空闲后继续发送、短 SSE 断流、SDK 重连和旧后台任务完成后的自动恢复：
  检查同会话一次提交、真实进度持续、终态确认，以及失败后的草稿/暂停队列。
- 终端结束后继续正文、隐藏页面再切回、待 AskUser/权限时收到快照：确认正文和
  待回答卡持续可见。应用层 ACK 能发现可见页面漏收，仍需核对实际 DOM 与交互，
  不能将状态已应用当作完整绘制保证。
- Stop 未确认时应保持该轮锁定并能重试，不能假装完成；取消准备/设置更新失败
  不应迟到发送原请求，也不能覆盖用户新编辑的草稿。
- 原生 IDE 的完整握手必须由根会话证明；运行中 Reload 不承诺无缝连接。
  CLI 升级时复核 0.228 feature snapshot 兼容措施和 daemon 生命周期内配置冻结影响。

### Restore 单独验收

- 原生文件恢复成功、后继 attach 失败后，相同消息重试应只接管后继；更改锚点应拒绝。
- 编辑草稿、恢复明细、连接等待和实际错误应保留；不能用固定短等待清掉进度。
- 当前待接管标记仅在 Runtime 生命周期内有效，跨 Reload 保留尚未实现/验证。
  在具备明确恢复目标和本轮授权的隔离环境验证后，才评估是否需要持久化契约调整。
- 不对用户现有工作区自动 Rewind/重发来完成验收；普通文件列表读取不等于真实恢复。

  原生 Diff/扩大上下文不能读取后来磁盘内容冒充原比较版本。
