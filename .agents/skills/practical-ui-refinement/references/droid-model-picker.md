# Droid 模型选择器：一次已认可的整改

这是复用思路的实例，不是所有页面都必须照搬的模板。用户认可的是简单、紧凑、实用的结果；具体结构仍由当前任务决定。

## 问题与取舍

| 观察到的问题 | 本次做法 | 可以复用的判断 |
| --- | --- | --- |
| 模型长列表与推理等级的关系不清楚 | 主菜单放“推理强度”和“模型”，分别展开子菜单；模型列表保留搜索、来源分组和当前项勾选 | 相关但可独立调整的维度，可以分层组织 |
| `Fable 5.1` 与 `· 高` 被撑到按钮两边 | 去掉无必要的固定最小宽度和自动外边距，连续显示“Fable 5.1 · 高”，保留右侧箭头 | 先改善信息之间的距离，不靠更多装饰分组 |
| 搜索结果少、缺少能力时仍显示很多说明 | 列表随内容收紧，有继承选项时不重复提示空结果；没有强度数据时隐藏强度入口 | 删除重复信息，同时保留真实的加载与错误反馈 |
| 宽度变窄后侧边菜单越界 | 菜单根据 Radix 提供的可用空间收缩，实际核对 520px 页面边界 | 桌面截图好看仍不足以确认弹层边界正确 |
| 新菜单重复选择当前模型会触发默认等级重置 | 只有模型 ID 改变时才通知业务层；重选当前模型保留用户已调等级 | 换组件时也要保留原来的值变更语义 |
| 参考截图有 Fast、Context 等选项 | 按用户范围暂不新增这些开关，等级来自实际 SDK 目录 | 学习参考交互前先核对自身调用能力 |
| 压缩模型是否也能选强度不明确 | 核对当时使用的 SDK `0.9.1`，压缩配置没有独立强度参数，因此继续直接选模型 | 模型能力与特定操作的可配置能力分别核对 |

以上 SDK 结论仅描述该次整改。后续任务应检查项目实际依赖版本及导出类型，不把这里的版本、模型名单或等级写成永久规则。

## 本项目的真实页面验收

复用内置浏览器的 Browser Dev Client，连接当前 Extension Host；管理页入口为 `/live?view=management`。连接端口和 Token 来自当次启动，不写入 skill、截图说明或提交。没有可用连接时按项目现有开发入口恢复，不能自行拼造认证链接。

此次核对了实际模型与等级、搜索键盘操作、重复选择、草稿回显与撤销、空结果及窄屏边界。没有保存模型配置或发送模型请求。后续只验证自身改动影响的行为；这份案例不额外授权测试、安装或发布。
